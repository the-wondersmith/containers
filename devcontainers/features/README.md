# Dev Container Features

[Dev Container Features](https://containers.dev/implementors/features/) published
from this repository.

## Published

| Feature                  | Reference                                        | Description                                                       |
|--------------------------|--------------------------------------------------|-------------------------------------------------------------------|
| [`mise`](src/mise)       | `ghcr.io/the-wondersmith/containers/mise:1`      | Installs [`mise`](https://mise.jdx.dev/) with optional activation. |

## Not published

| Feature                                    | Description                                                                  |
|--------------------------------------------|------------------------------------------------------------------------------|
| [`feature-testing`](src/feature-testing)   | Test-only helper. Referenced by scenarios locally; deliberately not released. |

`feature-testing` lives under `src/` because that is where the test harness
resolves scenario feature names from, **not** because it is meant to ship. The
publish workflow carries an explicit exclusion list and fails if a name on that
list no longer exists, so a rename can't silently start publishing it.

## Layout

```
devcontainers/features/
├── src/<feature>/          # devcontainer-feature.json, install.sh, README.md
└── test/<feature>/         # test.sh, scenarios.json, <scenario>.sh
```

## Testing

```sh
cd devcontainers/features

# everything
devcontainer features test --project-folder . --features mise

# one scenario
devcontainer features test --project-folder . --features mise --filter with_version

# skip scenarios, run only the autogenerated test.sh
devcontainer features test --project-folder . --features mise --skip-scenarios
```

Scenarios build real images and run real installs, so a full pass pulls several
base images and hits the network.

## Publishing

Handled by [`devcontainer-features.yaml`](../../.github/workflows/devcontainer-features.yaml),
which runs the suite on every pull request touching this directory and publishes
on a manually dispatched run. Features are published individually rather than as
a collection, so the exclusion above is enforced at the point of publish.
